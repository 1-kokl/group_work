# 06 漏洞清单

> 对应任务书第 7 周节点「SAST/DAST 与依赖扫描」的「漏洞清单」交付物。
> 按严重度分级；「阻断级」问题均附修复计划与责任人（对应验收要点「阻断级问题有修复计划和责任人」）。

严重度定义：**阻断级（Blocker）**= 上线前必须修复；**高（High）**= 尽快修复；**中（Medium）**= 计划内修复；**低（Low）**= 择机修复。

## 1. 阻断级（Blocker）

### B-1 私钥明文入库
- **位置**：`certs/rootCA.key`、`app/sm2_key.txt`、`app/sm4_key.txt`、`bank_sm2_key.txt`
- **问题**：CA 私钥、SM2/SM4 密钥直接提交进 Git 仓库，任何有仓库权限者即可伪造证书/签名。
- **修复计划**：
  1. 从仓库移除所有私钥文件并加入 `.gitignore`；
  2. 重新生成密钥，改用环境变量 / 密钥管理服务（KMS）注入；
  3. 历史提交中的密钥视为已泄露，需轮换并吊销旧证书。
- **责任人**：后端负责人

### B-2 SM2 签名随机数使用非加密随机源
- **位置**：`app/services/数据安全层访问.py:160`（`random.randint(1, 10**64)`）
- **问题**：SM2 签名对随机数 k 有严格安全要求，使用 `random`（梅森旋转，可预测）可能导致私钥泄露（ECDSA/SM2 已知攻击面）。第 4 周安全隧道已用 `secrets`，此处为遗留旧实现。
- **修复计划**：改用 `secrets.token_hex(32)`（`SM2_Utils.py` 已是正确写法，统一替换）。
- **责任人**：后端负责人

### B-3 依赖组件存在高危 CVE
- **位置**：`requirements.txt`
- **问题**：`cryptography 45.0.6`（13 个 CVE，被安全隧道/证书使用）、`PyJWT 2.12.1`（18 个 CVE）、`requests 2.32.3`、`Werkzeug 3.1.6`。
- **修复计划**：
  1. `cryptography` 升到 ≥ 46.0.7（必要时 50.0.0）；
  2. `PyJWT` 升到 ≥ 2.15.0（或评估后移除，因主链路未用）；
  3. `requests` 升到 ≥ 2.33.0、`Werkzeug` 升到 ≥ 3.1.9；
  4. 升级后跑回归（`test_rbac.py` / `test_secure_tunnel.py`）。
- **责任人**：后端负责人（依赖升级）＋ 前端负责人（npm audit 结果）

## 2. 高（High）

### H-1 数据库配置硬编码弱口令
- **位置**：`app/services/数据安全层访问.py:48-62`（`user=root`、`password=123456`）
- **修复计划**：改为从环境变量读取，不写死默认口令。
- **责任人**：后端负责人

### H-2 CORS 通配放行
- **位置**：`run.py:28`（`CORS(app, resources={r"/api/*": {"origins": "*"}})`）
- **修复计划**：收敛为前端域名白名单，禁止 `*`。
- **责任人**：后端负责人

## 3. 中（Medium）

### M-1 JWT `jti` 熵不足
- **位置**：`app/services/数据安全层访问.py`（`jti` 用 `random.randint`，仅 6 位数字）
- **修复计划**：改用 `secrets.token_hex(16)`。
- **责任人**：后端负责人

### M-2 银行服务 debug 模式与密钥日志
- **位置**：`mock_bank.py`（`debug=True`）、启动时打印密钥前段
- **修复计划**：生产关闭 debug，去除密钥日志输出。
- **责任人**：后端负责人

### M-3 前端 token 存 localStorage（XSS 可窃取）
- **位置**：`ecommerce-frontend/docs/SECURITY.md` 已自述该风险
- **修复计划**：改用 httpOnly Cookie（短期可先加强 CSP + 输入转义兜底）。
- **责任人**：前端负责人
