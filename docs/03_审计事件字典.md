# 03 审计事件字典

> 对应任务书第 2 周节点「RBAC 与 MFA 设计」中的「审计事件字典」交付物。
> 实现代码：`app/services/audit_service.py`（`audit_logs` 表 + `write_log`）。
> 事件 `action` 统一用大写常量；`result` 取值：`success` / `denied` / `failure`。

## 1. 日志表结构（`audit_logs`，位于 `user.db`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增主键 |
| `ts` | TEXT | 时间戳 `YYYY-MM-DD HH:MM:SS` |
| `user_id` | INTEGER | 操作者用户 ID（可空，登录失败等场景无） |
| `username` | TEXT | 操作者用户名 |
| `role` | TEXT | 操作者角色 |
| `action` | TEXT | 事件动作（见下表，已建索引） |
| `resource` | TEXT | 操作对象（user/totp/audit/product/…） |
| `resource_id` | TEXT | 对象 ID（如被改角色的用户 ID） |
| `result` | TEXT | `success` / `denied` / `failure` |
| `ip` | TEXT | 来源 IP |
| `detail` | TEXT | 补充说明（如 `buyer: user -> merchant`） |

## 2. 事件字典

### 2.1 认证类（AUTH_*）

| action | 触发场景 | resource | 典型 result | 敏感 |
| --- | --- | --- | --- | :-: |
| `AUTH_LOGIN_SUCCESS` | 登录成功（含 TOTP 二次通过） | - | success | |
| `AUTH_LOGIN_FAIL` | 密码错误 / 用户不存在 / 锁定 | - | failure | ✅ |
| `AUTH_LOGIN_TOTP_REQUIRED` | 管理员/审计员密码通过，进入二次验证 | - | success | |
| `AUTH_LOGOUT` | 注销（令牌拉黑） | - | success | |

### 2.2 TOTP 双因素类（TOTP_*）

| action | 触发场景 | resource | 典型 result | 敏感 |
| --- | --- | --- | --- | :-: |
| `TOTP_BIND_INIT` | 发起绑定，生成密钥与扫码串 | totp | success | |
| `TOTP_BIND_CONFIRM` | 首个验证码确认，TOTP 启用 | totp | success | |
| `TOTP_VERIFY_SUCCESS` | 二次验证通过 | totp | success | |
| `TOTP_VERIFY_FAIL` | 动态验证码错误 | totp | failure | ✅ |
| `TOTP_REPLAY_BLOCKED` | 同一窗口验证码被重复使用 | totp | denied | ✅ |
| `TOTP_RECOVER` | 使用恢复码登录成功 | totp | success | |
| `TOTP_RECOVER_FAIL` | 恢复码无效或已使用 | totp | failure | ✅ |
| `TOTP_DISABLE` | 禁用 TOTP | totp | success | |
| `TOTP_DISABLE_FAIL` | 缺少有效验证码/恢复码，禁用被拒 | totp | denied | ✅ |
| `TOTP_RESET_BY_ADMIN` | 管理员代重置 TOTP（兜底边界） | totp | success | ✅ |

### 2.3 用户管理类（USER_*，仅管理员）

| action | 触发场景 | resource | 典型 result | 敏感 |
| --- | --- | --- | --- | :-: |
| `USER_MANAGE_LIST` | 查询用户列表 | user | success | |
| `USER_CREATE` | 创建用户并指定角色 | user | success | |
| `USER_ROLE_CHANGE` | 变更用户角色 | user | success | ✅ |
| `USER_STATUS_CHANGE` | 启用/禁用用户 | user | success | ✅ |
| `USER_PASSWORD_RESET` | 管理员重置密码 | user | success | ✅ |

### 2.4 审计类（AUDIT_*）

| action | 触发场景 | resource | 典型 result | 敏感 |
| --- | --- | --- | --- | :-: |
| `AUDIT_VIEW` | 查看审计日志 | audit | success | |
| `AUDIT_EXPORT` | 导出审计日志 | audit | success | |
| `AUDIT_SECURITY_EVENTS` | 查询安全事件（越权/失败/重放） | audit | success | |

### 2.5 访问控制类

| action | 触发场景 | resource | 典型 result | 敏感 |
| --- | --- | --- | --- | :-: |
| `ACCESS_DENIED` | 越权访问被拒绝（403） | 对应权限点 | denied | ✅ |

## 3. 敏感/安全事件汇总（供 `audit/security-events` 查询）

`app/api/admin_api.py:183-196` 中「安全事件」聚合查询关注以下事件：

```
ACCESS_DENIED, AUTH_LOGIN_FAIL, TOTP_VERIFY_FAIL, TOTP_REPLAY_BLOCKED, TOTP_RECOVER_FAIL
```

## 4. 验收要点对照

| 验收要点 | 落地 |
| --- | --- |
| 每个事件都有对应记录 | 上方 23 个 `action` 在代码中均有 `write_log` 调用点，逐一可对 |
| 管理员关键操作可追溯 | `USER_ROLE_CHANGE` / `USER_STATUS_CHANGE` / `USER_PASSWORD_RESET` / `USER_CREATE` 全部落库并含 `resource_id` 与 `detail` |
| 越权可追溯 | `ACCESS_DENIED` 在 `rbac._deny()` 中强制写入 |
