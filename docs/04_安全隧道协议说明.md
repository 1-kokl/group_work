# 第4周安全隧道协议与密钥管理方案

本周先完成协议冻结、密钥边界和后端纯函数骨架。当前分支为 `week4-secure-tunnel`，后续将按白名单接口接入 Axios 和 Flask。

## 协议字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `version` | string | 固定 `v1` |
| `key_id` | string | 服务端 SM2 公钥标识，例如 `server-sm2-2026-01` |
| `alg` | string | 固定 `SM4-GCM+SM2` |
| `nonce` | base64url | 每次请求随机 12 字节，服务端 TTL 内只能使用一次 |
| `ts` | integer | Unix 秒，服务端允许 ±300 秒 |
| `wrapped_key` | base64 string | 用服务端 SM2 公钥封装本次 16 字节 SM4 会话密钥 |
| `ciphertext` | base64 string | SM4-GCM 密文 |
| `tag` | base64 string | 16 字节 GCM 认证标签 |

AAD 固定为 `version|key_id|ts|nonce|HTTP_METHOD|path`。方法或路径被替换时，GCM 认证失败。

## 密钥管理边界

- 服务端长期 SM2 私钥由 `TunnelKeyManager` 统一加载，后续迁移到环境变量或密钥服务；不进入请求日志和错误响应。
- 服务端只向前端提供 `key_id` 和公钥，不下发 SM2 私钥。
- 每次请求生成新的 SM4 会话密钥和 Nonce；会话密钥只存在于封装、加解密期间。
- Nonce 当前由线程安全内存存储维护，下一步替换为 Redis/SQLite TTL，以覆盖多进程和重启场景。
- 演示密钥不能用于生产；应用层加密不能替代 HTTPS/TLS。

## 已落地骨架

- `app/services/secure_tunnel.py`
  - `TunnelEnvelope.from_dict()`：字段和长度校验
  - `TunnelKeyManager`：SM2 封装/解封会话密钥
  - `SecureTunnel.seal()`：SM4-GCM 加密和信封生成
  - `SecureTunnel.open()`：时间窗、Nonce、防重放、GCM Tag 和 JSON 解密
- `evidence/week4/`：用于保存测试输出、抓包和脱敏协议样例。
