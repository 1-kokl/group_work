# 第4周安全隧道协议、拦截器与验收说明（v2）

## 交付范围

本周交付包含可运行的 Flask 演示接口、浏览器端密码适配层/ Axios 拦截器、协议说明和真实 HTTP 请求/响应记录。Demo 地址为 `/week4-demo`。

安全隧道是应用层保护，仍必须使用 HTTPS；它不替代 JWT、RBAC、订单幂等和业务金额校验。

## 协议

请求 JSON 恰好包含：

|字段|规则|
|---|---|
|`version`|`v2`|
|`key_id`|服务端 SM2 公钥指纹，例如 `sm2-xxxxxxxxxxxxxxxx`|
|`alg`|`SM4-GCM+SM2`|
|`nonce`|随机 12 字节，无填充 Base64URL，单次使用|
|`ts`|Unix 秒，和服务端相差不超过 300 秒|
|`wrapped_key`|SM2 C1C3C2 封装的 16 字节 SM4 会话密钥|
|`ciphertext`|SM4-GCM 密文，规范 Base64|
|`tag`|16 字节 GCM 标签，规范 Base64|

AAD 为 `v2|SM4-GCM+SM2|key_id|ts|nonce|HTTP_METHOD|path|request`。修改路径、方法或元数据会使认证失败。

服务端解密并认证请求后，用 HKDF-SHA256 从请求会话密钥派生响应密钥。响应请求绑定字段 `request_nonce`，AAD 追加 `request_nonce|status`，因此浏览器不需要、也不会收到服务端私钥。

## 密钥边界

- 浏览器每次请求用 Web Crypto 随机生成 16 字节会话密钥和 12 字节 Nonce。
- 浏览器只从 `/api/v1/tunnel/config` 获取公钥和 `key_id`。
- 服务端隧道私钥在被 `.gitignore` 忽略的 `.local/week4/sm2.json` 中生成；生产环境应改用 KMS/环境密钥。
- 重放记录在 `.local/week4/replay.sqlite3`，使用 SQLite 原子插入，支持本地多进程和重启后的时间窗。
- 密文、会话密钥和私钥不写入日志；HTTP 样例只保留信封字段。

## 代码对应关系

- `app/services/secure_tunnel.py`：信封校验、SM4-GCM、SM2 封装、响应派生密钥、时间窗和持久化 Nonce。
- `app/middleware/secure_tunnel.py`：白名单接口解密、请求上下文、失败审计。
- `app/api/tunnel_api.py`：配置接口和 echo 演示接口。
- `ecommerce-frontend/src/services/tunnel_axios.js`：Axios 请求/响应拦截器；只对显式 `secureTunnel` 的白名单 POST 生效，拒绝查询串和自动重试。
- `ecommerce-frontend/src/utils/secure_tunnel.js`：浏览器 SM2/SM4-GCM、HKDF 适配层。

## 本地验收

1. 在项目根目录执行 `$env:PYTHONUTF8='1'; python test_secure_tunnel.py`，应看到 8 条 PASS。
2. 启动 Flask：`python -c "from run import app; app.run(host='127.0.0.1', port=5000, debug=False)"`。
3. 打开 [http://127.0.0.1:5000/week4-demo](http://127.0.0.1:5000/week4-demo)。点击“正常请求”应为 200 并显示解密响应；同一页面点击“重复请求”应为 400；“篡改密文”和“过期请求”应为 400。
4. 前端构建：进入 `ecommerce-frontend` 后执行 `npm run build`。允许仓库原有的依赖和图标警告，但不能有编译错误。

## 证据

`evidence/week4/captured-request.json` 和 `captured-response.json` 必须由本地真实 HTTP 调用生成；记录时间、URL、状态码和完整信封，不写入任何私钥或明文会话密钥。它们是演示证据，不等同于生产环境 PCAP。

## Axios 实际接入

演示页“正常请求（Axios）”调用共享拦截器 `installSecureTunnelInterceptors`。异常按钮使用 Fetch 重发或篡改信封，用于验证服务端拒绝路径。此前 Demo 只用 Fetch 的版本已替换。

## 抓包证据的范围

当前 `captured-*.json` 是程序从真实本地 HTTP 调用保存的请求/响应记录，不是浏览器 HAR 或 Wireshark PCAP，不能把它们描述为网络抓包。现场可在浏览器 Network 中查看 echo 的 Request Payload；若需要提交抓包文件，应在 Network 中导出 HAR，并确认不包含登录令牌、Cookie 或私钥。
