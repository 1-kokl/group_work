# 01 权限矩阵（RBAC 设计）

> 对应任务书第 2 周节点「RBAC 与 MFA 设计」中的「权限矩阵」交付物。
> 本文档与代码逐条对齐，代码实现见 `app/middleware/rbac.py` 的 `PERMISSION_MATRIX`。

## 1. 模型

用户（User）→ 角色（Role）→ 权限（Permission），三级映射。

| 角色常量 | 角色名 | 说明 |
| --- | --- | --- |
| `user` | 普通用户（买家） | 浏览商品、下单、支付、管理个人资料 |
| `merchant` | 商户（卖家） | 在 `user` 基础上可创建/管理**自有**商品 |
| `admin` | 管理员 | 用户管理、角色/状态变更、审计、TOTP 代重置 |
| `auditor` | 审计员 | 只读审计日志、导出，安全事件查询 |

代码常量：`ROLE_USER` / `ROLE_MERCHANT` / `ROLE_ADMIN` / `ROLE_AUDITOR`（`rbac.py:24-28`）。

## 3. 两类权限控制

1. **功能级权限（矩阵内）**：`require_permission("product.create")` —— 角色是否被允许执行某类操作。
2. **数据级权限（矩阵外）**：商户仅能操作 `owner == 自己` 的商品；订单天然按 `owner` 自限。在服务层按资源归属二次校验，防止「横向越权」（商户 A 改商户 B 的商品）。

## 4. 实现要点（与代码对齐）

- 装饰器：`require_permission` / `require_any_permission` / `require_role`（`rbac.py:91-128`）。
- 装饰器顺序：必须置于 `@jwt_required` **之上**（外层），先认证后授权（见 `rbac.py` 顶部注释）。
- 越权统一处理：`_deny()` 写 `ACCESS_DENIED` 审计日志并返回 403（`rbac.py:75-88`）。
- 角色来源：`request.user_info["role"]`（JWT 载荷注入，见 `jwt_auth.py`）。

## 5. 验收要点对照

| 验收要点 | 落地位置 |
| --- | --- |
| 角色无越权 | `require_permission` 矩阵拒绝 + 数据级归属校验；`test_rbac.py` 场景一/二/三覆盖 |
| 管理员关键操作可追溯 | 所有写操作经 `write_log` 落库（见 `03_审计事件字典.md`） |
| 恢复流程有边界 | TOTP 防重放计数器 + 恢复码一次性 + 管理员代重置边界（见 `02_TOTP流程图.md`） |
