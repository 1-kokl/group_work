# 第4周本地测试与使用说明

当前本地分支：`week4-secure-tunnel`。所有改动只在本地，不需要 push 才能测试。

## 这次完成了什么

第4周要求的是“安全隧道 Demo”，核心是把敏感 JSON 从明文请求体改成一个可验证的应用层信封：

1. 后端用每次请求随机生成的 16 字节 SM4 会话密钥执行 SM4-GCM。
2. 服务端 SM2 公钥封装会话密钥，服务端私钥只在后端解封，不通过接口返回。
3. Nonce 使用 12 字节随机值，服务端在时间窗内只接受一次。
4. `ts` 默认允许前后 300 秒，过期请求直接拒绝。
5. GCM AAD 绑定版本、密钥 ID、时间戳、Nonce、HTTP 方法和路径，改路径或方法会认证失败。
6. Flask 提供 `/api/v1/tunnel/config` 和 `/api/v1/tunnel/echo` 演示接口；失败写 `SECURE_TUNNEL_REJECT`，成功写 `SECURE_TUNNEL_ACCEPT`。
7. Axios 增加显式 `secureTunnel: true` 开关，只对白名单敏感接口封装，不影响普通接口。
8. 第2周遗留的 pending MFA token 越权已修复，并加入回归测试。

应用层隧道是课程演示机制，不能替代生产环境 HTTPS/TLS。

## 手工接口检查

启动后端：

```powershell
$env:PYTHONUTF8='1'
python -c "from run import app; app.run(host='127.0.0.1', port=5000, debug=False)"
```

另开终端检查公开配置：

```powershell
curl.exe http://127.0.0.1:5000/api/v1/tunnel/config
```

配置响应只应包含 `key_id`、算法、版本、时间窗和 SM2 公钥，不应包含私钥。

完整演示直接运行 `test_secure_tunnel.py`，它使用 Flask test client，不依赖端口、浏览器或外部银行服务。

## 前端接入方式

`ecommerce-frontend/src/services/http.js` 已支持：

```js
http.post('/api/v1/tunnel/echo', payload, {
  secureTunnel: { keyId: 'server-sm2-2026-01' }
});
```

前端密码实现通过 `ecommerce-frontend/src/utils/secure_tunnel.js` 的 `setSecureTunnelCrypto()` 注入。这样可以把经过评审的 SM2/SM4-GCM 浏览器实现接入，而不把会话密钥写入存储或日志。未注入 bridge 时，普通接口照常工作，标记 `secureTunnel: true` 的接口会明确报错，不会静默降级为明文。
