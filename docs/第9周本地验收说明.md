# 第9周本地验收说明

本次补充的目标是完成登录、商品查询、下单三个接口的性能基线、优化和同环境复测，并提供可复现原始证据。操作入口见 [性能验收说明](../performance/README.md)，统计结果见 [性能实测结果](../evidence/week9/comparison/性能实测结果.md)。

本次结果：三个接口在10/30/50并发下的九个条件均达到门槛，p95下降43.32%至91.53%，优化版错误率均为0%。13项新增回归、32项RBAC/MFA检查和8项安全隧道检查均通过。

首次50并发登录受到全机CPU竞争影响，原始结果未通过该行门槛。该轮保留不删；随后按预先记录的计划交替复核双方各两轮，主表的50并发登录采用全部复核数据，其余八个条件沿用原来的两轮。详见实测报告中的复核说明和 `confirmation/plan.json`。

验收时先核对基线与优化目录的 `environment.json`，再查看 `comparison/comparison.csv` 中各接口、各并发的p95、吞吐和错误率。JMeter脚本在 `performance/jmeter/`，每轮原始记录在 `evidence/week9/` 的对应阶段和条件目录。

业务优化包括商品卖家批量查询、筛选排序索引、SQLite连接复用与WAL、原生SM3、短时有界JWT验签缓存，以及订单/库存统一事务。库存扣减使用带库存条件的更新，订单号改用UUID随机部分；重复下单与取消在事务中验证状态。

测试工具为每轮创建独立数据副本和测试密钥。现有演示库、证书私钥和银行数据库不作为压测写入目标。新增与既有验收回归输出见 `evidence/week9/regression-final/`；测试结果必须以实际日志为准。

本机使用SQLite和本机负载发生器，当前测量不覆盖生产网络、真实银行服务或应用层隧道接入业务接口后的端到端性能。部署或安全链路变化后应按同样口径重新采集。

第7周的本地扫描入口、前后修复证据和原始报告也已补齐，见 [本地安全复核报告](第7周本地复核报告.md)。其中依赖告警仍有未闭环项，第9周性能达标不等于最终安全验收全部通过。
